# Трубадур для Android 4.1+

Порт клиента [`youtube-ios`](https://github.com/computershik/youtube-ios) —
того, что написан для iOS 5.1, который сам является портом
[`youtube_uwp`](https://github.com/zemonkamin/youtube_uwp) для Windows 10
Mobile. Нижняя граница здесь — **Android 4.1** (API 16), верхняя —
актуальная.

Требование к порту было то же, что и в iOS-версии: **дизайн должен
в точности соответствовать оригиналу.** Числа не пересчитывались ни разу
за три платформы — в UWP размеры заданы в эффективных пикселях, в UIKit
в точках, в Android в независимых точках, и все три единицы означают одно
и то же: примерно 1/160 дюйма.

## Состояние

Приложение собирается и работает на устройстве. Проверялось на Android 13
и на Android 5.1.1 (Sony Xperia Z Ultra) — воспроизведение, перемотка,
вход по QR-коду, PO-токен, скачивание. На 4.1 и 4.4 проверено только то,
что приложение запускается.

Перед сборкой под старые системы обязательна проверка вызовов:

```
./gradlew :app:lintDebug
```

Она ловит обращения к тому, чего на нижней границе нет. Один такой вызов
(`TextView.setLetterSpacing`, API 21) ронял приложение при запуске
на 4.1 и 4.4, а на 5.1 и новее был незаметен вовсе.

Что осталось перенести, перечислено в [ОСТАЛОСЬ.md](ОСТАЛОСЬ.md); список
собран не по памяти, а сверкой подписей — см. `tools/audit-strings.py`.

## Чего в порте нет и почему

Половина iOS-версии здесь **не нужна**, и это главное отличие.

Там `AVPlayer` не умеет ни DASH, ни фрагменты MP4 из памяти, поэтому путь
до картинки был такой:

    подача → разбор боксов fMP4 → ремукс в MPEG-TS → локальный сервер
    HTTP на 127.0.0.1 → синтезированный плейлист HLS → AVPlayer

Это `YTMp4` (691 строка), `YTTsMuxer` (621) и `YTHlsProxy` (2599) — почти
четыре тысячи строк со своими бедами: пометка точек входа битом
`random_access_indicator`, часы PCR на ключевых кадрах, постоянство
токенов сегментов, `SIGPIPE` при закрытии сокета, ATS, запрещающая
незашифрованную петлю.

Здесь ничего этого нет: `FragmentedMp4Extractor` из ExoPlayer разбирает
те же самые фрагменты внутри плеера, а `MediaMuxer` сводит дорожки при
скачивании. От нас требуется одно — подавать байты.

Цена: на API 16–17 `MediaMuxer` ещё нет, и скачивание там берёт готовый
progressive-поток (360p) вместо сведения двух дорожек.

## Как собрать

Нужен JDK 8 и Android SDK. Пути задаются в `local.properties`
и `gradle.properties` (`org.gradle.java.home`).

```
./gradlew :app:assembleDebug
```

Готовая сборка — `assembleRelease`; она не пишет журнал (`BuildConfig.LOG`
равен `false`, и R8 выбрасывает и вызовы, и их аргументы).

Подпись берётся из `keystore.properties` рядом с проектом; нет файла —
собирается неподписанный релиз, что удобно на чужой машине и на сервере.
Подписывается обеими схемами: **v1** ради нижней границы (схема v2
появилась в Android 7.0, и всё, что старше, о ней не знает — подписанный
только ею файл на 4.1 не установится) и **v2** ради верхней. Свёртка
у v1 при `minSdkVersion 16` берётся SHA-1: SHA-256 в подписи архива
понимают только с API 18.

Проверить готовый файл:

```
apksigner verify --min-sdk-version 16 --verbose app-release.apk
```

Версии закреплены и подняты быть не могут: AGP 4.1.3 и Gradle 6.8.3 —
последние, что уживаются с minSdk 16; OkHttp 3.12.13 — последняя ветка
с поддержкой API 9–20; ExoPlayer 2.13.3 — последняя с minSdk 16.

## Проверки

```
python tools/check-strings.py     # подписи есть во всех 12 языках
python tools/audit-strings.py     # что из оригинала ещё не перенесено
```

Первая обязательна перед сборкой: ключом перевода служит русская строка,
и подпись, которой нет в таблице, молча останется русской — заметит это
только тот, кто смотрит на другом языке.

## Устройство

    ru.computershik.troubadour
    ├── App, Log, Settings, Strings, Text, Notify   основание
    ├── net/    Http+TLS, Json, Api (InnerTube), Auth, WebAuth,
    │           PoToken, PlayerJs, NSig, Downloads
    ├── player/ Sabr, Ump, Proto, Streams, SabrSource, PlayerEngine,
    │           Subtitles, Storyboard, SponsorBlock, Chapters
    └── ui/     Theme, Metrics, Views, Screen+Nav, Shell, разделы,
                страница ролика, настройки

Экран один — `MainActivity`. Разделы нижней панели живут внутри одной
оболочки, переходы вглубь — своей стопкой видов над ней, свёрнутый в окно
ролик — над всем. В оригинале так же: `Home.xaml` в UWP
и `YTShellViewController` под невидимым `UINavigationController` в iOS.
Activity на каждый экран не годится: переключение вкладки пересоздавало бы
ленту, а поворот — плеер.

## Что стоит знать, прежде чем править

Правила, каждое из которых стоило отладки. Они же записаны комментариями
там, где действуют.

**Разметка — руками.** Виды меряются и раскладываются числами оригинала,
а не через XML. При этом в Android вид обязан быть **измерен** до укладки:
`TextView` строит раскладку текста при обмере, и подпись, уложенная в рамку
без обмера, рисуется мимо неё. Для этого есть `View.frame(…)` — меряет
и укладывает разом; ручных `layout()` в проекте быть не должно.

**`UILabel` центрирует текст по вертикали, `TextView` прижимает к верху.**
Поэтому `label()` ставит `Gravity.CENTER_VERTICAL` по умолчанию.

**JavaScript исполняется, а не открывается как адрес.**
`loadUrl("javascript:" + код)` разбирает содержимое по правилам адреса:
`%` читается как начало шестнадцатеричной пары, а `#` обрывает строку.
На шестидесяти килобайтах BotGuard это отсекало половину, и PO-токен
не получался ни разу.

**Веб-виду нужно окно.** Программа проверки размечает работу по кадрам
отрисовки, а у вида вне окна кадров не бывает. Решатель лежит в окне
двумя пикселями в углу — как в оригинале, где он вынесен за край рамкой
`-500,-500`.

**Подача SABR — одна на две дорожки.** Разговор с ней идёт под замком:
источников два, потоков загрузки тоже два, а перечень набранного, счётчики
кусков и сам поток ответа общие. После прыжка обе дорожки ведутся к одному
мигу, пока обе на него не встанут, иначе они расходятся на секунды —
и это выглядит как застывший кадр при живом звуке.

**Времена фрагментов настоящие.** В fMP4 от подачи лежит `baseMediaDecodeTime`,
и лента у плеера начинается сразу с него. Прибавлять к позиции плеера
смещение прыжка нельзя — время удвоится.

**Кадр рисуется в `TextureView`, а не в `SurfaceView`.** Второй дешевле,
но его слой — отдельное окно системного композитора, и место с размером
доходят туда только штатным проходом отрисовки. Вся разметка здесь идёт
руками, и такое окно за ней не поспевает: кадр на миг появляется целиком,
а потом возвращается в прежний прямоугольник. `TextureView` — обычный вид,
где положили, там и рисует. В iOS этой беды нет вовсе: `AVPlayerLayer` —
простой слой.

**Пустой успешный ответ и отсутствие ответа — разные вещи.** Путать их
в сообщениях нельзя: первое значит «здесь ничего нет», второе — «сети
не было».

**`accountReadMask` обязателен** в запросе списка каналов: без него сервер
молча отдаёт одного владельца вместо всех бренд-каналов.

**У reel-эндпоинтов номер TV-клиента 7, а не 85.**

**Продолжение ленты берётся тем же клиентом, что отдал первую страницу.**

**Список категорий SponsorBlock кодируется целиком**, а не по одной.

**`signatureTimestamp` запоминается вместе с номером сборки плеера.**
